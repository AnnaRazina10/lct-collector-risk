# Current Task: EDA исходных данных

## Статус

Первичный потоковый EDA по годовым журналам 2019-2026 выполнен. Результаты сохранены в `reports/eda/`: основной отчет `reports/eda/eda_report.md`, таблицы в `reports/eda/tables/`, графики в `reports/eda/figures/`, промежуточная машинно-читаемая статистика в `reports/eda/raw_stats/`.

## Задача

Текущая задача - провести разведочный анализ данных для кейса ЛЦТ по прогнозированию аварий и управлению ремонтами инженерных коллекторов. Результат EDA должен помочь понять структуру данных, качество журналов, покрытие справочников, характер тревожных событий, возможную формализацию таргета и ограничения, которые нужно учитывать при построении ML-модели и продукта.

## Что нужно получить

Нужно подготовить информативные графики, таблицы и выводы по данным. Подписи на графиках должны быть на русском языке, кроме общепринятых терминов на английском, таких как Precision, Recall, target, feature, missing rate, correlation.

## Основные направления анализа

Нужно изучить состав файлов, годы, объемы, число событий, число каналов, число объектов и распределение событий во времени. Нужно проверить справочники, связи между `ид_канала_данных` и `ид_объект`, покрытие каналов из журналов справочником каналов, покрытие объектов справочником объектов и наличие неизвестных или пропущенных сущностей.

Нужно провести проверки качества данных: пропуски, дубли, некорректные даты и времена, невозможные значения датчиков, выбросы, аномальные годы или периоды, частые повторяющиеся значения, неравномерность потоков событий, подозрительные каналы и резкие изменения распределений.

Нужно построить статистики признаков и агрегатов: распределение типов инженерных систем, типов датчиков, тревожных и нетревожных событий, активности каналов, активности объектов, сезонности, суточных и недельных паттернов, доли тревог по типам датчиков и объектам.

Нужно исследовать связь признаков с потенциальным таргетом. Важно проверить, можно ли однозначно определить target из предоставленных данных, что именно может быть положительным событием, какие есть прокси-таргеты и какие риски есть у такой разметки.

Нужно построить таблицы со статистикой признаков, покрытием, корреляцией признаков с target и корреляцией признаков друг с другом. Для категориальных признаков нужно использовать подходящие агрегаты и сравнения долей, а не только числовую корреляцию.

Желательно найти нетривиальную особенность данных: например, аномальный год, нестабильный тип датчика, группу каналов с необычным поведением, сильную зависимость тревожности от типа системы, проблему связи справочников, повторяющийся паттерн ложных тревог или другую особенность, которая может повлиять на стратегию решения.

## Критерии готовности

Задача считается выполненной, когда есть понятный EDA-результат с графиками, таблицами и текстовыми выводами; отдельно описано качество данных; отдельно описано покрытие справочников; отдельно сформулировано, однозначно ли определяется target и какие варианты target можно использовать; отдельно выделены риски и найденные нетривиальные особенности данных.

## Где должны появиться результаты

Результаты EDA должны быть сохранены в проекте так, чтобы команда могла их открыть без повторного анализа. Для ноутбуков используется `notebooks/`, для переиспользуемого кода - `src/`, для отчетов, графиков и таблиц - отдельная директория, которую нужно добавить в `inventory.md` после создания.
