# Погодный контекст Москвы: отдельный исследовательский эксперимент

Основание: оригинал ТЗ 2026, §13 разрешает интеграцию данных метеослужб через открытые API. Данные коллекторов, идентификаторы и координаты объектов наружу не передаются. Запрос содержит только общую точку Москвы 55.75, 37.62, публичные даты и названия погодных величин.

Источник — [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), явно выбран ERA5, суточные значения в Europe/Moscow. Выгрузка охватывает 2024-12-01—2026-06-30: средняя, минимальная и максимальная температура, осадки, средняя относительная влажность, среднее давление на уровне моря и поверхности. ERA5 — реанализ на сетке около 25 км; значения характеризуют общий фон Москвы, а не точную погоду анонимизированных объектов.

Проверенная выгрузка содержит 577 дат без пропусков. API вернул ячейку 55.75, 37.5 и высоту 152 м; исходно запрошенная долгота 37.62 сохранена отдельно в provenance. Снимок получен 2026-09-28; точное время UTC и контрольные суммы записаны в provenance.

Запуск из корня репозитория:

```sh
.venv/bin/python src/modeling/fetch_weather_context.py
```

Повторный запуск использует сохранённый ответ с проверкой запроса и SHA256. Новый снимок данных требует явного `--refresh`; для сохранения прежнего снимка укажите другую папку через `--output-dir`.

Результаты в `data/raw/external/` (папка исключена из Git):

- `московскийконтекст.json` — исходный ответ API без изменений.
- `московскийконтекст.csv` — суточные факты с ключом `source_date`.
- `московскийконтекст_lag7.csv` — признаки `weather_lag7_*` с ключом `date` и проверочным `source_date`.
- `московскийконтекст.provenance.json` — точный URL, запрос, полученная ячейка сетки, дата получения, единицы, лицензия, цитирование, SHA256 и результаты проверок.

Для дня прогноза D таблица признаков содержит только погоду дня D−7. Соединять следует по `date` с проверкой `many_to_one`, а не по номеру строки. Диапазон дат признаков — 2024-12-08—2026-07-07; при подготовке конкретной витрины его следует ограничить датами этой витрины. Сам исходный CSV нельзя присоединять к D как погоду D. Скрипт проверяет непрерывность дат, пропуски, единицы, физические ограничения, уникальность ключа и соответствие значений исходной дате.

**Только исследовательский ablation; в основную v2 не включено.** Текущая выгрузка использует доступную сейчас версию реанализа. [Copernicus](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview) указывает задержку ранней ERA5T около пяти суток и возможность отличий финальной версии спустя 2–3 месяца. Исторические `available_at` и версии поправок API не предоставляет. Сдвиг семь суток ограничивает календарное подглядывание, но не доказывает строгую доступность именно этих значений в прошлом. Нельзя представлять эксперимент как strict point-in-time или подтверждение производственного эффекта; обучение и оценка качества этим скриптом не выполняются.
