# Объектная архивная демонстрация и локальный журнал

Интерфейс по умолчанию открывает отдельный объектный режим. Он прогнозирует хотя бы одно зарегистрированное тревожное сообщение по каналам объекта в заданные сутки. Физическая поломка, её причина и срок ремонта этой меткой не подтверждаются. Канальный режим сохранён и переключается отдельной кнопкой; его метрики относятся к другой единице наблюдения и другому горизонту.

## Подтверждённая модель и время выпуска

Используется прежняя сохранённая `models/object_risk_probe.txt`, без переобучения, ансамбля или подбора нового порога. SHA-256: `e0924c042197f5e393efb014319259929cf0a7c82890bbe4e47e3ae790f1c493`. Признаки и порог берутся из `reports/object_risk_probe/configuration.json`, согласованность проверяется с `reports/object_forward_check/checks.json`.

| --- | --- |
| История признаков | По 28 июня 2026 включительно |
| Отсечение истории | 28 июня 2026, 23:59:59 МСК |
| Расчётный выпуск | 29 июня 2026, 00:00 МСК |
| Целевое окно | [30 июня 2026, 00:00; 1 июля 2026, 00:00) МСК |
| Минимум от выпуска до начала окна | 24 часа |
| Единица прогноза | Объект, связанный с каналами в справочнике |
| Карточки в выпуске | 78 объектов; 47 выше замороженного порога |
| Порог | 0.3345231006565093; выбран на октябре–ноябре 2025 |

На ранее выполненной проверке сохранённой модели: Precision ≈ 0.569, Recall ≈ 0.596, AP ≈ 0.621 на 14 040 объект-днях (78 объектов × 180 дней выпуска). Точные результаты находятся в `reports/object_forward_check/metrics.csv`. Период 2026 ранее использовался в других исследованиях, поэтому проверка не называется полностью слепым тестом. Числа 70% / 50% не являются требованием оригинального ТЗ; сравнение с ними может служить только инженерным ориентиром.

`score` используется для ранжирования и сравнения с порогом; он не калиброван как вероятность физической неисправности. Высокая распространённость объектной тревоги отличается от распространённости тревоги отдельного канала. Объектные показатели нельзя выдавать за улучшение канальных метрик.

## Воспроизводимый экспорт

Из корня репозитория:

```bash
.venv/bin/python src/modeling/export_object_demo.py
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8765
```

Открыть `http://127.0.0.1:8765/?mode=object`; прежний режим — `?mode=channel`. При занятом порте используйте свободный локальный порт. Экспорт требует подготовленных суточных таблиц 2025–2026, справочников, сохранённой модели и ранее полученного архива объектной проверки.

Экспортёр вызывает `object_risk_probe.prepare("2026-06-28")`, проверяет фактическое отсечение истории, уникальность объектов и отсутствие будущих меток у прогнозируемых строк. Календарный `target_dayofweek` вычислен для D+2 и известен заранее. В модели ровно 71 признак в сохранённом порядке. После расчёта оценок и вкладов SHAP отдельно загружаются архивные исходы. Оценки после физического отсечения будущей истории полностью совпали с архивом проверки: максимальная разность 0.

Результаты в исключённой из Git папке `data/app`:

- `object_risk_demo.json` — выпуск и приватные архивные исходы для отдельного раскрытия;
- `object_demo_checks.json` — контроль причинности, хеша и совпадения предсказаний;
- `object_demo_screen.png` — реальный снимок проверенного интерфейса.

Файл экспорта не раздаётся статическим сервером. Обычные API-ответы, карточки, снимки решений и черновики не содержат `actual_*` или `outcome`. Архивный исход возвращает только отдельный endpoint после явного действия пользователя. Такая граница относится к API; локальный владелец файла по-прежнему может прочитать архивный JSON.

## Интерфейс и API

В объектном режиме доступны список по оценке риска, поиск, фильтры «без тревоги в день признаков» и «выше порога», вкладка схемы групп и карточка объекта. Схема использует иерархию справочника; она не изображает реальные координаты, протяжённость коллектора или связи оборудования. Карточка показывает доступность записей, тревожившие каналы, положительные вклады признаков, рекомендуемую проверку и отдельную кнопку архивного исхода. Отсутствие записей не интерпретируется как исправность.

| Запрос | Назначение |
| --- | --- |
| `GET /api/health` | Доступность двух архивных наборов |
| `GET /api/risks?mode=object` | Объектные карточки и параметры выпуска |
| `GET /api/risks/{id}?mode=object` | Снимок карточки без будущего исхода |
| `GET /api/risks/{id}/outcome?mode=object` | Явное раскрытие архивного факта |
| `POST /api/tickets` | Локальный черновик; поля `risk_id`, `entity_mode`, `note` |
| `GET /api/tickets?mode=object` | Сохранённые черновики режима |
| `POST /api/feedback` | Новое решение диспетчера со снимком прогноза |
| `GET /api/feedback?mode=object` | Последние 200 решений режима |
| `GET /api/journal?mode=object` | Последние 200 решений и черновиков вместе |

Параметр `mode` принимает `channel` или `object`. API по умолчанию сохраняет прежний `channel`; UI явно запрашивает выбранный режим. В истории отсутствие `mode` означает все режимы. Идентификаторы карточек из другого режима отклоняются. Дополнительно доступны короткие маршруты `/risks`, `/health`, `/tickets/draft`, `/feedback`.

Обратная связь содержит `risk_id`, `entity_mode`, `operator`, `decision`, `reason`, `note`. Решения: `monitor`, `inspect`, `alarm_confirmed`, `alarm_not_confirmed`. Основания: `needs_inspection`, `planned_work`, `sensor_or_connection`, `journal_verified`, `other`. Комментарии ограничены 2000 символами. Имя диспетчера вводится локально и не является подтверждённой корпоративной идентичностью.

SQLite по умолчанию: `data/app/tickets.sqlite3`; переменная `LCT_TICKET_DB` позволяет задать отдельную базу. Старые канальные черновики сохраняются при миграции. Повторный черновик идемпотентен и сохраняет исходную заметку; последующие решения добавляются отдельными записями. В каждой новой записи фиксируются карточка, оценка, модель, порог и время прогнозного окна на момент решения. Будущий исход не включается в снимок. Внешние заявки и уведомления не отправляются.

## Проверки и границы готовности

Три прежних API-теста и девять новых регрессионных тестов успешно проверяют разделение режимов, сокрытие будущих исходов, идемпотентность, сохранение исходного снимка после изменения набора, журнал, миграцию прежней базы и причинные проверки экспортёра. Команда:

```bash
.venv/bin/python -m unittest tests.test_api tests.test_api_object tests.test_api_object_export -v
```

29 сентября 2026 через Chrome проверены фактическая загрузка обоих режимов, объектная схема, сохранение тестового решения и черновика в отдельной временной базе, отображение их в журнале и явное раскрытие архивного исхода. Ошибок JavaScript в проверенной сессии не обнаружено. Для проверки использован локальный сервер на порту 8772 и отдельная база `/private/tmp/lct-object-ui-20260929-agent.sqlite3`; тестовые записи не попали в основную базу.

Не закрыты производственные требования: подключение потока текущих данных и автоматический выпуск новых прогнозов; классификация подтверждённых физических инцидентов и проверка на такой разметке; калибровка вероятностей; корпоративные роли, вход и аудит идентичности; интеграция с системой заявок; реальная пространственная карта; производственная база, резервирование и эксплуатационное защищённое развёртывание. Локальный журнал хранит решения и их снимки, а не полный исторический поток всех прогнозов. Архивный интерфейс сам по себе не означает готовность к эксплуатации. Нагрузочные и ресурсные измерения оформлены отдельно в `reports/runtime_validation/`.
