# Выпуск прогноза из доступной истории

`src/serving/object_forecast.py` рассчитывает объектный прогноз сохранённой моделью по дневным пакетам. Для расчёта больше не требуется дата в архиве оценки или файл с будущими исходами. Каждый выпуск сохраняется целиком с версией модели, контрольной суммой входа, временем доступности пакетов и объяснениями.

Проверенный режим — **историческое воспроизведение**, а не подключение к текущему потоку СМВУ. Время доступности суточных пакетов в упражнении смоделировано: следующий день, 00:00 МСК. Фактическое время сохранения в базе хранится отдельно. В рабочей системе задержки доставки/расчёта потребуют отдельного определения времени выпуска и проверки реального упреждения.

## Запуск

Нужны локальные `daily_2025.parquet`, `daily_2026.parquet`, два исходных справочника и замороженная модель из `reports/object_risk_probe/configuration.json`. Данные и веса исключены из Git. Модель и справочники проверяются по контрольным суммам; обучение при выпуске не происходит.

```bash
.venv/bin/python src/serving/object_forecast.py \
  --first-feature-date 2026-06-26 --last-feature-date 2026-06-28 \
  --database data/app/forecast_replay_validated.sqlite3 --report-dir reports/forecast_replay/validated

LCT_TICKET_DB=data/app/forecast_replay_validated.sqlite3 .venv/bin/python -m uvicorn api.main:app \
  --host 127.0.0.1 --port 8780 --workers 1
```

В объектном режиме интерфейса выберите сохранённый выпуск. Исходная архивная демонстрация остаётся отдельным пунктом. Новые выпуски не содержат будущих исходов и не предлагают их раскрытие; оценка качества этих выпусков не подменяется общей метрикой модели.

## Доступность и неизменность

- Входной пакет описывает полный закрытый день. Дата, уникальность канал-дня, неотрицательные целые счётчики и время доступности проверяются до использования.
- Неполученный пакет вызывает отказ расчёта; явный пустой пакет допустим. Отсутствие сообщений объекта не доказывает исправность.
- Из нескольких версий одного дня используется последняя, доступная к историческому времени выпуска. Конфликтующие версии с одинаковым временем отклоняются.
- Поздняя корректировка может участвовать в последующем выпуске. Ранее сохранённый выпуск не перезаписывается. Повторная публикация того же содержимого идемпотентна.
- Модель получает признаки только до D включительно; прогноз относится к D+2. Последние неизвестные целевые метки остаются пустыми и не входят в признаки.
- Начальная история до первого дня воспроизведения принимается как полный неизменяемый bootstrap. Реальные времена прибытия старых записей и исторический реестр датчиков отсутствуют; они не восстановлены искусственно.
- Исторический выпуск замороженной модели разрешён лишь после 30 ноября 2025, когда завершился период исходов для подбора порога. Более ранние даты отклоняются и в CLI, и непосредственно при inference.
- Пустой результат чтения архивной даты не считается подтверждённым пустым пакетом. CLI отклоняет такую дату; явный пустой пакет допустим только у вызывающего адаптер источника, подтверждающего его комплектность.

## Выполненная проверка

[Три выпуска](../reports/forecast_replay/runs.json) содержат по 78 объектов. Чтение очередного дневного пакета, сборка доступной истории, признаки, расчёт и сохранение заняли **1,90–2,02 с** на локальном компьютере. Из замера исключены первоначальное чтение bootstrap и загрузка модели. Распаковка исходных событий, сеть и действующая СМВУ не измерены.

[Независимое сравнение](../reports/forecast_replay/verification.json) подтвердило точное совпадение всех **234 оценок** с прежним сохранённым прогнозом. Повторный расчёт дал идентичный payload. Изменённые будущие и запоздавшие пакеты не изменили более ранний выпуск; гипотетическая поздняя корректировка изменила 38 оценок следующего выпуска, при этом все три сохранённых выпуска остались неизменными. Гипотетические прогнозы в базу не публиковались.

Извлечение построителя признаков в функцию, принимающую данные в памяти, отдельно сверено с кодом коммита `6a4f775`: **42 432 строки × 73 столбца совпали точно**, включая категории, цели и покрытие. [Проверка рефакторинга](../reports/forecast_replay/refactor_check.json).

После добавления двух ограничений дат расчёт [повторён окончательной версией](../reports/forecast_replay/validated/runs.json) в отдельной базе `forecast_replay_validated.sqlite3`: 1,20–1,32 с на выпуск, все [проверки идентичности и причинности](../reports/forecast_replay/validated/verification.json) прошли. Изменение версии кода породило новые идентификаторы; прежние выпуски сохранены. Реальные запросы 01.07.2026 (за границей архива) и 01.06.2025 (до подбора модели) [отклонены](../reports/forecast_replay/validated/boundary_checks.json). Разница времени двух коротких запусков не заявляется как оптимизация производительности.

```bash
.venv/bin/python scripts/verify_forecast_replay.py
.venv/bin/python -m unittest discover -s tests -p test_forecast_replay.py -v
```

Проверка сохранения и API описана в [истории выпусков](forecast_history.md), резервного копирования — в [backup/restore](backup_restore.md). Исторический replay не закрывает требования подключения к потоку, реальных задержек доставки, корпоративной авторизации и высокой доступности.

На отдельной восстановленной копии базы дополнительно проверен [перезапуск настоящего HTTP-сервиса](../reports/forecast_replay/http_restart.json): три выпуска и 234 карточки совпали до/после завершения процесса; решение, введённое через браузер и явно помеченное тестовым, сохранило привязку к выпуску. Проверена штатная остановка и повторный запуск на macOS; отказ узла, автоматическое переключение и HA не моделировались. Полный локальный набор: [82 прошедших теста](../reports/forecast_replay/integration_tests.log).
