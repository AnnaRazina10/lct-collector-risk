# Локальная демонстрация риска

Из корня репозитория после установки requirements-experiments.lock.txt:

```sh
.venv/bin/python src/modeling/export_risk_demo.py
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8765
```

Открыть http://127.0.0.1:8765. Для экспорта нужны локальные результаты улучшенной модели и кеш дневной витрины. Команды их получения находятся в reports/improved_v1/report.md.

## Что показывает интерфейс

- Реальные оценки сохранённой модели на 29.06.2026 для прогноза сообщений о тревоге на 30.06.2026.
- Расчёт для 11 497 каналов; 4 530 имели записи за последние 7 дней. Среди последних 199 превышают выбранный на validation порог. Интерфейс показывает только первые 100 по оценке, поиск и фильтр действуют внутри этих 100.
- Карточка канала: история событий, положительные вклады SHAP в логарифмических шансах модели, рекомендация проверить журнал. SHAP не доказывает причинность.
- Факт следующего дня раскрывается отдельным действием. В признаки прогноза он не включён.
- Черновики сохраняются только локально в data/app/tickets.sqlite3. Повторная заявка на ту же карточку возвращает прежний черновик. Отправки во внешнюю диспетчерскую систему нет.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют временную причинность и изоляцию каналов, метрики/порог, разделение прогноза и будущего исхода, сохранение и повторную запись черновика, проверку входных данных API. В браузере проверены поиск, выбор карточки и раскрытие архивного исхода. Общий набор дополнен проверками последующих исследовательских итераций.

## Границы

Архивная демонстрация использует v1 и не подключена к потоку СМВУ. Суточная агрегация не обеспечивает обновление каждые 5 минут. Score не калиброван как вероятность физической поломки; next-day горизонт v1 не гарантирует минимум 24 часа упреждения. Оригинал ТЗ не задаёт обязательных порогов P/R — их нужно обосновать при проектировании. Более поздние модели и отдельная объектная проверка 24–48 часов описаны в README, но автоматически в интерфейс не подменялись. Локальный сервер слушает только 127.0.0.1; для промышленного размещения нужны подключение данных, авторизация и интеграция заявок.
