# Найденные исходники призовых решений ЛЦТ

Проверено 28.09.2026. Код скачан в references для чтения, сторонние приложения не запускались. Копии исключены из Git нашего проекта. Названия команд, место и соответствие кейсу проверяются отдельно: репозиторий участника не обязательно содержит именно победившую работу.

## GigaWin — второе место, ЖКХ ЛЦТ-2024

- [Исходники](https://github.com/xEnotWhyNotx/GigaWin), commit `9e78758a912eb628b739966466b776dd660c3416`.
- [Результаты организатора](https://innoagency.ru/news/news/v_moskve_podveli_itogi_hakatona_lidery_cifrovoy_transformacii_20240630): первое место spatial_band, второе GigaWin, третье «Адера».
- Автор репозитория — Sergey Novichkov; Сергей Новичков указан в составе GigaWin в [официальном документе](https://i.moscow/upload/lending/lct2024/4ef034.pdf). README и файлы относятся к прогнозу аварий ЖКХ 2024 года.
- Изучены `Prediction_pypeline.py`, `research_and_model.ipynb.ipynb`, страницы приложения. Совмещают погоду, отопление, жалобы и параметры домов; строят отклонения от температурных графиков и показатели утечки. В notebook есть CatBoost, линейные модели, случайный лес; интерфейс содержит прогноз и симуляцию.
- Важное ограничение: `train_test_split` в notebook перемешивает строки. Такое качество нельзя переносить на наш временной прогноз. Нормативные графики отопления неприменимы к произвольным каналам коллектора.
- Переносим принципы: осмысленные отклонения от рабочего режима и сценарий решения для оператора. Чужие численные результаты не используем как наши.

## waico.tech — второе место, «Северсталь» ЛЦТ-2023

- [Исходники](https://github.com/waico/severstal-exhauster), commit `cb85fb1be3b120919c0e257628e9016ec7dc0696`.
- Второе место приведено в [публикации о результатах «Северстали»](https://www.novostiitkanala.ru/news/detail.php?ID=169937); участие и второе место также указаны в [публикации участника команды](https://ru.linkedin.com/in/stepan-andreev-804845135).
- README описывает три отдельные задачи: неисправность М1, интервалы аномального режима М3 и остаточное время до простоя М1. Доступны notebooks, обучение, FastAPI/Vue, мониторинг через MLflow/Grafana.
- Изучены `Task2Step2Model.py`, notebooks задач 1–3. Есть переразметка неисправностей, часовая агрегация, отдельные модели оборудования/целевых событий, сравнение классификаторов через PyCaret, CatBoost для остаточного ресурса.
- Ограничения: в RUL notebook есть случайное разделение строк; в M3-скрипте медианы рассчитываются по всему переданному массиву и есть ветка объединения train/test при отсутствии класса. Для нашей временной проверки нужны статистики только из прошлого и отдельный контроль такой ветки.
- Переносим принципы: разделение обнаружения текущей аномалии и будущего отказа, аудит разметки, модели по механизму проблемы, законченный путь от данных до оператора.

## Что не следует ошибочно называть найденным победным кодом

- У [yasevplaton](https://github.com/yasevplaton) есть `spatial-band-hack` и `spatial-band-6-task-frontend`. README второго прямо указывает ЛЦТ-2021, задачу 6. Считать их исходниками победы в ЖКХ-2024 нельзя.
- Публичные исходники первых мест InfoVision по «Северстали»-2023 и spatial_band по ЖКХ-2024 пока не подтверждены.
- `waico/tsad` — общая библиотека автора, а не автоматически конкурсная версия `severstal-exhauster`.
- В выбранных checkout GigaWin-2024 и severstal-exhauster отдельного файла лицензии не найдено. Чужой код в наш продукт не переносился; собственная реализация использует общие методы и независимо написанный код.

## Применение к нашему проекту

1. Завершено: неизменная цель и сопоставимый тест, точное воспроизведение baseline, CatBoost/LightGBM, история канала и объектный контекст. Результаты находятся в `reports/improved_v1/report.md`.
2. Реализован продуктовый шаг: карточка риска с подтверждающими признаками, отдельная маркировка текущей тревоги и черновик заявки. Ретроспективный показ должен явно обозначать дату и известность будущего исхода.
3. Следующая ML-итерация: нормальные режимы по типу канала, технические эпизоды и наблюдаемость. Перед изменением цели согласовать её с формулировкой ТЗ; новый target нельзя выдавать за улучшение прежней метрики.

Исходные инструкции запуска в чужих README рассматриваются как описание проектов, а не как распоряжение выполнять их команды.
