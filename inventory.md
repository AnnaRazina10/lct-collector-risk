# Inventory проекта

## Общая формулировка задания

Проект выполняется для кейса ЛЦТ 2026 "Прогнозирование аварий и управление ремонтами инженерных коллекторов Москвы". Нужно подготовить веб-сервис с предиктивной аналитикой для диспетчерской и эксплуатационной службы: модель должна оценивать риски инцидентов, отказов датчиков или оборудования на горизонте не менее 24 часов, а интерфейс должен помогать диспетчеру понимать причины риска, приоритизировать проверки, фиксировать решения и формировать превентивные заявки.

## Правило ведения inventory

`inventory.md` является картой проекта. При создании новой директории или при изменении назначения существующей директории нужно обновлять этот файл. В inventory фиксируется, где что лежит и зачем это может понадобиться для решения задачи. Конкретные технические итерации, временные планы и ход выполнения задач здесь не описываются.

## Структура проекта

### `README.md`

Главная страница репозитория. Нужна для краткого объяснения проекта, состава решения и входа в документацию для команды, экспертов и жюри.

### `.gitignore`

Список файлов и директорий, которые не должны попадать в Git. Важен для защиты репозитория от тяжелых данных, моделей, аудио и локальных артефактов.

### `inventory.md`

Карта проекта: описание директорий, файлов верхнего уровня и назначения материалов.

### `current task.md`

Описание текущей активной задачи. Этот файл нужен, чтобы команда видела, какая работа сейчас выполняется, какой ожидается результат и какие критерии готовности у задачи.

### `archive tasks/`

Папка для завершенных задач. После окончания активной задачи ее описание можно переносить сюда как отдельный markdown-файл, чтобы сохранять историю принятых решений и результатов.

### `docs/`

Документация по кейсу и решению. Здесь лежат материалы, которые помогают понять задачу, требования, данные, стратегию и запуск проекта.

Содержимое:

- `case.md` - описание кейса, контекст, пользователи, направления прогнозирования.
- `requirements.md` - требования к продукту, ML, API, интерфейсу, безопасности и сдаче.
- `data_description.md` - описание локального датасета, файлов, колонок и первичных выводов.
- `strategy.md` - продуктовая и ML-стратегия решения.
- `setup.md` - инструкция по локальной подготовке проекта, данным и GitHub.
- `README_before_overwrite.md` - сохраненная предыдущая версия README перед заменой.

### `data/`

Данные проекта.

Содержимое:

- `data/raw/` - локальные исходные данные хакатона. Папка не коммитится, потому что содержит тяжелые архивы и CSV. Нужна для EDA, обучения моделей, построения фичей и проверки гипотез.
- `data/samples/` - небольшие примеры данных, которые можно безопасно коммитить и использовать для тестов, демонстраций структуры и документации.

### `notebooks/`

Jupyter-ноутбуки для аналитики, EDA, проверки гипотез, визуализаций и первых ML-экспериментов. Нужны для исследовательской работы и быстрого обмена наблюдениями внутри команды.

### `src/`

Основной код обработки данных и машинного обучения. Здесь должны жить переиспользуемые модули для загрузки данных, очистки, генерации признаков, обучения моделей, оценки качества и inference.

### `api/`

Backend и REST API будущего сервиса. Здесь должны размещаться endpoints для прогнозов, списка рисков, объектов, датчиков, черновиков заявок и feedback от диспетчера.

### `web/`

Frontend будущего диспетчерского интерфейса. Здесь должен размещаться дашборд рисков, карточка прогноза, журнал событий, схема/карта объектов и элементы работы с заявками.

### `artifacts/`

Производные материалы, полученные в ходе работы. Часть артефактов может быть полезна для команды и коммититься, а тяжелые промежуточные файлы должны оставаться локальными.

Содержимое:

- `artifacts/transcripts/` - расшифровки и конспекты видео Q&A по кейсу.
- `artifacts/audio/` - локально извлеченное аудио для транскрибации. Папка не коммитится.

### `models/`

Локальные модели и веса, например модель Whisper для транскрибации. Папка не коммитится, потому что содержит тяжелые бинарные файлы и не является частью исходного кода проекта.

## Локальные исходные данные

Локальные данные находятся в `data/raw/` и включают годовые архивы журналов событий за 2019-2026 годы, пример журнала событий и справочники каналов/объектов. Эти данные нужны для EDA, проверки качества, построения таргета, анализа покрытий, поиска аномалий, генерации признаков и обучения моделей. В GitHub они не загружаются.

## Что может понадобиться для решения задачи

Для решения задачи могут понадобиться: исходные журналы событий, справочник каналов датчиков, справочник объектов, материалы ТЗ, расшифровка Q&A-встречи, EDA-отчеты, графики, таблицы статистик, код обработки данных, описание выбранного таргета, baseline-модель, API, диспетчерский интерфейс, инструкция запуска, документация по ограничениям и допущениям.
