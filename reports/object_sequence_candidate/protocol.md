# Предварительный протокол временной нейросети

Зафиксирован до обучения 29.09.2026. Эксперимент отдельный: рабочие модели и выбор их порогов не изменяются.

- Единица: объект-день. Цель `target_any_object_alarm_d_plus_2` — любое зарегистрированное тревожное событие на D+2, не подтверждённая физическая авария. Признаки известны к D+1 00:00; целевое окно начинается через 24 часа.
- Исходная функция: `object_risk_probe.prepare(end_date='2025-12-31')`. Сразу после подготовки отбрасываются строки после 30.11.2025. Декабрьские значения не используются в преобразованиях, окнах, обучении, ранней остановке, выборе или отчётах качества. Период 2026 не загружается.
- Train: feature day <= 28.09.2025, последние целевые сутки 30.09.2025. Tune: 01.10–28.11.2025, последние целевые сутки 30.11.2025. Разрыв не позволяет целевым окнам train пересечь tune.
- Два заранее заданных кандидата: одна общая GRU, окна 28 и 56 дней включительно по D. Скрытое состояние 32, один слой; выход Linear(32,16), ReLU, Linear(16,1). Идентификатор объекта не является входом сети.
- На каждом шаге: `alarm_today`, `observed_today`; `log1p(alarm_count)`, `log1p(observed_channels)`, `log1p(fault_count)`, `log1p(no_power_count)`, `log1p(events_count)`. Средние/стандартные отклонения пяти численных признаков рассчитываются только на train. Дополнительная маска отличает отсутствующую предысторию от реального дня без сообщений.
- Никаких будущих признаков наблюдаемости. Все объект-дни входят в оценку, включая дни без сообщений, как в исходном object probe. Отсутствие тревожной записи не доказывает исправность оборудования.
- AdamW: learning rate 0.001, weight decay 0.0001; BCEWithLogits, естественная частота классов; batch 256; максимум 40 эпох, patience 6 по AP tune, минимальное улучшение 0.0001. Ограничение 240 секунд обучения на кандидат, CPU 3 потока. Seed 84 для обоих кандидатов.
- Победитель — больший AP на всём tune. Порог max-F1 на том же tune приводится только как исследовательская характеристика; калибровка/финальный порог в этой задаче отсутствуют.
- Соперники: всегда тревога, текущая тревога, замороженная по train частота объекта; существующий LightGBM object probe только если сохранённые ключи и метки tune совпадают полностью.
- Проверки: изменение будущего не меняет прошлое окно; окна не пересекают объекты; конец окна соответствует D; край периода обучения и цель D+2; воспроизведение после загрузки. Калибровка, refit и test требуют следующего отдельного шага после сообщения результатов.
