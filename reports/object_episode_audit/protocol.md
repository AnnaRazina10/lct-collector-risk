# Замороженный протокол аудита начала зарегистрированных тревожных эпизодов

Записан до расчёта итоговых метрик аудита. Аудит не обучает модели, не меняет веса, пороги, бюджет предупреждений и состав проверяемых строк.

## Объект и время

Используем прежние 14 040 прогнозов для 78 объектов. Feature days D: 31.12.2025–28.06.2026. Выдача происходит D+1 в 00:00. Целевой день T = D+2: 02.01.2026–30.06.2026, то есть начало окна находится за 24 часа после выдачи. Для эпизода T засчитывается только предупреждение из точной строки D=T−2. Предупреждения за другой срок не добавляем.

## Заранее заданные определения

Основное определение gap=1: зарегистрированное начало E(T)=1, если на объекте есть хотя бы одна тревожная запись в день T, а за весь календарный день T−1 нет тревожных записей. Дополнительные чувствительности gap=3 и gap=7 требуют отсутствия тревожных записей во все g предыдущих полных календарных дней. Для проверки есть история 2025 года. При неполном календарном контексте начало считается неопределённым, а не отрицательным; такие строки показываются отдельно и не скрываются.

Дни с тревогой, не удовлетворяющие условию начала, обозначаем как повторные тревожные дни по данному gap. При gap=3/7 отдельные тревоги через короткие тихие интервалы входят в тот же объединённый эпизод.

Отсутствие записи означает только отсутствие записи в выгрузке. Даже наличие хотя бы одного события на объекте не доказывает полное покрытие всех датчиков. Нулевые тревожные записи не означают физическую исправность, а начало зарегистрированного эпизода не является подтверждённым новым физическим отказом.

## Замороженные модели и пороги

Берём `data/interim/object_combined_test.parquet`: `previous_frozen`, `lightgbm_control`, `selected`. Порог старого контроля берём из `reports/object_risk_probe/configuration.json` через модуль `object_risk_probe.OUT`; пороги двух новых вариантов из `reports/object_combined/selection.json`. Никакой оптимизации порога по новой эпизодной разметке. Идентичность исходных ключей, target, score и хешей проверяем.

## Показатели

Для каждого gap и модели показываем полное число объект-дней и тревожных дней, число зарегистрированных начал, долю заранее предупреждённых начал, повторные тревожные дни и предупреждения на них. Предупреждения без нового эпизода делим на предупреждения в повторный тревожный день и предупреждения в день без тревожной записи. Они не обозначаются безусловно ложными по прежней цели. Доля предупреждений, совпавших с началом, имеет новый эпизодный смысл и не подменяет прежний precision.

Наблюдаемость показываем отдельно: наличие записей на feature day D; все/часть/ни одного дня с записями в предшествующем gap; наличие записей на T. Все начала входят в основной итог, независимо от этих диагностических страт. Отдельные cohort по последующим данным используются только для описания, а не для выбора. Месячные итоги группируем по целевому дню T и явно показываем выдачу T−1.

## Проверки

Проверяем границы объектов, календарные пропуски, точное D+2 выравнивание, разделение начал и повторов, сохранение всех строк и равенство исходных сохранённых прогнозов. Разметка T не меняется от мутаций после T. Мутации событий после D должны оставлять прогноз D неизменным при проверке замороженного inference. Наблюдаемость будущего используется только в описании разметки, никогда в новых признаках.

## Ограничение вывода

Аудит является последующим анализом ранее исследованного периода 2026, а не новой слепой проверкой. Он измеряет разрыв между прогнозом любой тревоги и началом зарегистрированного эпизода. Возможный следующий эксперимент формулируется отдельно и не запускается в рамках этого аудита.
